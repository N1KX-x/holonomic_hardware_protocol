WORK RECORD - Go2 conformal constraint tightening experiment
Friday 2026-10-09 to Tuesday 2026-10-13
======================================================================

Project:  hardware data collection for "Conformal Constraint Tightening
          for Chance-Constrained Motion Planning with Unknown Dynamics"
          (Natraj, Sinopoli, Kantaros, arXiv:2607.22409).
Robot:    Unitree Go2, commanded open-loop with body-frame velocities
          (vx, vy, omega), each command held for dt = 2 s.
Sensing:  OptiTrack / Motive motion capture, rigid body ID 1006.
Code:     https://github.com/N1KX-x/holonomic_hardware_protocol
Protocol: hardware_protocol_full_holonomic.md

Quantities used throughout
  E    largest distance between the real robot and the nominal model
       during one run, checked at each 2 s segment boundary.
  q    90th percentile of E over the Phase 0 pilot runs.
  rho  planning margin = 1.75 x q. The protocol requires
       q < rho < goal radius. With goal radius 0.5 m this means
       rho < 0.5 m, i.e. q < 0.29 m.
  "fair test"  each run scored with a model fitted WITHOUT that run.

6. WHAT WE LEARNED ABOUT THE ERROR
----------------------------------------------------------------------

Patterns in the robot's response (achieved vs. commanded)
  Forward/backward  the achieved fraction FALLS as speed rises.
                    Forward 1.13 / 1.11 / 1.05 / 0.98 at 0.1 / 0.2 /
                    0.5 / 0.8 m/s; backward 1.07 / 1.01 / 0.96 / 0.86.
  Sideways          left almost exact; right a constant ~0.78.
  Turning           the achieved fraction RISES with speed: ~0.6 below
                    0.25 rad/s, ~0.80 near 1 rad/s.
  Side effects      fast forward walking also slides the robot left
                    (+0.045 m/s at 0.5 m/s, +0.074 at 0.8) and turns
                    it slightly left.
  Lag               about 10-12 % of the previous segment's speed
                    carries into the next segment (~0.23 s).

Where the remaining error comes from (with the six gains)
  - One 2 s segment, model started from the TRUE pose: error median
    8 cm, 90 % below 23 cm.
  - Average slip per segment: 1.5 cm forward, 2.2 cm left, whatever
    the command direction.
  - Heading is NOT the main cause: giving the model the true heading
    at every segment start leaves q unchanged (1.42 -> 1.37 m).
  - The error accumulates because nothing corrects the robot during
    a run. Random parts grow with the square root of the number of
    segments, steady slip grows in proportion. Over 20 segments,
    8-23 cm per segment becomes about 1 m.
  - To reach q < 0.29 m over 20 segments, each segment would need to
    be within about 6 cm at the 90 % level, with no steady slip.

The robot itself is repeatable
  Identical commands repeated 4-5 times (09-25 data) differ from each
  other by only 13-24 cm over 24 s / 9.6 m, about 2 % of distance.
  The scalar model is off by 10-15 %. So most of the error is the
  model being too simple, not randomness.

Corrections to earlier statements
  - "Heading drift is the main cause": wrong, see above.
  - "The drift is random and cannot be calibrated": wrong. Most of it
    is repeatable; simple models just cannot capture all of it.
  The PI summary document still contains the second statement.


----------------------------------------------------------------------
7. CONCEPTUAL POINTS DISCUSSED
----------------------------------------------------------------------

- q < 0.29 m is not written in the protocol. It follows from
  rho < goal radius (0.5 m) and rho = 1.75 x q. The protocol allows a
  multiplier from 1.5 to 2; the 90th percentile is a code choice.
- CP does not need a precise model to be valid. A poor model gives a
  large q, the inflated obstacles block every path, and no plan is
  accepted. A good model makes the method useful, not correct.
- Pure RRT has the same accumulated error but never measures it. In
  the paper's quadrotor study, plain RRT completes ~55 % of tasks and
  the tightened version 80-100 %.
- The paper has no hardware experiments, and its geometry is more
  forgiving: world 25 x 25, goal radius 5, start-goal distance >= 15.
  Scaled to the 5.6 m mat that is a goal radius of ~1.1 m (we use
  0.5 m) and a start-goal distance of ~3.4 m (we use 5.1 m).
- The paper only needs q to fit inside the goal. The protocol's extra
  rho = 1.5-2 x q makes the bar nearly twice as high.
