HOW TO RUN THE HOLONOMIC HARDWARE PROTOCOL ON THE TEST PC
==========================================================

Run every command below from inside the project folder on the test PC:

    cd /path/to/holonomic_hardware_protocol

Nothing needs to be built or installed. The code is plain Python (3.8+).
ROS is used only through Nova: each collection loads ~/nova/env.bash and
publishes velocity commands that the Nova Go2 driver forwards to the robot.


----------------------------------------------------------------------
0. ONE-TIME SETUP
----------------------------------------------------------------------

0.1 Copy this whole folder to the test PC (USB, scp, ...).

0.2 Edit config.py on the test PC:

    NOVA_ENV_FILE        path of Nova's env.bash (default ~/nova/env.bash)
    MOCAP_CLIENT_IP      the test PC's IP on the mocap network
    MOCAP_SERVER_IP      the Motive PC's IP
    RIGID_BODY_ID        the Go2 rigid-body ID in Motive
    CMD_VEL_TOPIC        topic the Nova driver subscribes to for velocity
    STOP_TOPIC           topic the Nova driver subscribes to for StopMove

    Experiment values (Phase 0 freezes these; changing them later means
    redoing Phase 0):
    DT_S, T_SEGMENTS, VX_MAX_MPS, VY_MAX_MPS, OMEGA_MAX_RADPS,
    TRANSLATIONAL_SPEED_MAX_MPS, GOAL_RADIUS_M, ROBOT_RADIUS_M,
    WORKSPACE_X_MIN_M / X_MAX_M / Y_MIN_M / Y_MAX_M

    Goal of both phases (every Phase 0 pilot plans to it):
    GOAL_X_M, GOAL_Y_M, GOAL_RADIUS_M

    Calibration (YAW_OFFSET_RAD, MARKER_TO_BODY_X_M / Y_M and the two
    POSITIVE_*_COMMAND_SIGN values) must be correct before Phase 0.
    To measure YAW_OFFSET_RAD, put the robot where it has about 1.3 m
    of free floor straight ahead and run:

    python3 yaw_offset_calibration.py --execute

    It walks straight forward (vx only, 0.25 m/s for 5 s), prints the
    measured yaw offset, and saves the run in data/yaw_calibration/.
    Copy the printed YAW_OFFSET_RAD line into config.py. Run it two or
    three times; the values should agree within a few degrees.

    Recommended for the first runs:
    REQUIRE_OPERATOR_CONFIRMATION = True
    (every run then asks you to type the pilot/trial name first)


----------------------------------------------------------------------
1. CHECKS THAT DO NOT MOVE THE ROBOT
----------------------------------------------------------------------

1.1 Check that Nova provides everything the command sender imports
    (should print "ok"):

    source ~/nova/env.bash && python3 -c "import rclpy, geometry_msgs.msg, unitree_go.msg; print('ok')"

1.2 Run the unit tests:

    python3 -m unittest discover -s tests -v

1.3 Start the Nova Go2 driver in its own terminal and leave it running.
    Then, in another terminal where you have run "source ~/nova/env.bash",
    confirm it is listening (each should show Subscription count >= 1):

    ros2 topic info /cmd_vel_out
    ros2 topic info /webrtc_req

1.4 Check mocap on its own. Logs the rigid body until Ctrl+C. Move the
    robot by hand while it runs; in the file, "tracked" should be 1 and
    x / y should change. Delete the file before running this again.

    python3 -m hardware.mocap_logger ~/mocap_check.csv


----------------------------------------------------------------------
2. PHASE 0 - MAP BOUNDARY, PILOTS, AND MODEL FIT
----------------------------------------------------------------------

Keep Nova running. Keep someone on the e-stop for every pilot.

2.1 Measure the boundary of the map (reads mocap only; the robot is not
    commanded):

    python3 robot_coordinate_getter.py

    Stand the robot on a corner of the usable area and press Enter;
    repeat for all four corners, then type q. Paste the four printed
    WORKSPACE_* lines into config.py. Phase 0 plans go right up to this
    boundary and the real robot drifts away from its plan, so leave free
    space (and mocap coverage) outside it.

2.2 Enter the goal in config.py: GOAL_X_M, GOAL_Y_M and GOAL_RADIUS_M.
    Phase 1 uses the same goal and keeps the goal radius shrunk by rho.

2.3 Collect one pilot. Put the robot anywhere inside the boundary, more
    than GOAL_RADIUS_M from the goal, not facing straight away from
    it, and run:

    python3 phase0.py --execute

    The program reads the robot's pose, plans an RRT path from there to
    the goal region around random virtual obstacles, prints the velocity
    commands, runs them, and saves everything as the next pilot:

    data/phase0/pilot_001/plan.csv       the velocity commands
    data/phase0/pilot_001/problem.json   start, goal, obstacles, seeds
    data/phase0/pilot_001/raw/           commands sent, mocap, publish log
    data/phase0/pilot_001/trajectory.png planned and real trajectory,
                                         drawn like the Phase 1 plots

    Repeat 2.3 as many times as you want; there is no fixed number. To
    see an example plan without moving the robot, leave out --execute.

    If a run fails (the RRT finds no path, mocap loses the robot, you
    press Ctrl+C, ...) it prints "Failed: ..." and saves nothing. Just run
    the command again; it uses the same pilot number.

2.4 When you have enough pilots, fit the model (no robot needed):

    python3 phase0analyze.py

    It searches for the gain and offset of each direction (+vx, +vy, -vy,
    +omega, -omega), the two turn lags and the walking yaw that minimize q, and
    prints them, E of every pilot, q and rho. The same text is saved as
    data/phase0/phase0_analysis.txt. It does NOT change config.py: to use
    the numbers, copy the MODEL_* lines from the text file into config.py. You can collect more pilots and run it
    again at any time; it always fits from scratch.

    Phase 0 is done when it prints "Status: ready" and config.py holds
    those lines (python3 main.py --validate checks this).
    If rho is not smaller than GOAL_RADIUS_M, the protocol's options are
    a shorter T, lower speeds, or a larger goal radius. Any of these means
    collecting the pilots again in a fresh data folder.

A data/phase0 folder from the earlier Phase 0 (it contains
plan_manifest.csv) is refused. Rename it, for example to phase0_old.


----------------------------------------------------------------------
3. PHASE 1 - MAIN COLLECTION
----------------------------------------------------------------------

3.1 Check that config.py still matches the Phase 0 result:

    python3 main.py --validate

3.2 Collect one trial. Put the robot anywhere inside the boundary, more
    than GOAL_RADIUS_M from the goal, and run:

    python3 main.py --execute

    Same as a Phase 0 pilot, except that the plan uses the frozen rho:
    virtual obstacles are kept PHASE1_ROBOT_RADIUS_M (0.35 m) + rho
    away, and the goal radius shrinks by rho. As in Phase 0, no margin is
    kept at the boundary. Everything is saved as the next trial:

    data/phase1/trial_001/plan.csv       the velocity commands
    data/phase1/trial_001/problem.json   start, goal, obstacles, seeds, rho
    data/phase1/trial_001/raw/           commands sent, mocap, publish log
    data/phase1/trial_001/trajectory.png planned and real trajectory

    The deviation E of the trial is printed when it finishes.
    There is no reset: walk the robot back yourself, then repeat 3.2 as
    many times as you want. To see an example plan without moving the
    robot, leave out --execute.

    If a run fails (the RRT finds no path, mocap loses the robot, you
    press Ctrl+C, ...) it prints "Failed: ..." and saves nothing. Just run
    the command again; it uses the same trial number.
    Never delete or rerun a trial because its E looks large or small;
    choosing trials by their E would bias the dataset.


----------------------------------------------------------------------
4. ANALYSIS (no robot needed)
----------------------------------------------------------------------

    python3 analyze_phase1.py

Prints E of every trial and how many have E <= rho, and writes
data/phase1/analysis/execution_metrics.csv.

To redraw trajectory plots (saved in each trial folder):

    python3 plot_phase1.py trial_003
    python3 plot_phase1.py all


----------------------------------------------------------------------
5. TRAINING DATA FOR A LEARNED MODEL
----------------------------------------------------------------------

See TRAINING_INSTRUCTIONS.txt. In short, repeat this for every trial:

    python3 collect_training.py --execute


----------------------------------------------------------------------
SAFETY NOTES
----------------------------------------------------------------------

- The safety stop uses the workspace in config.py (the rectangle inside
  the measured corners). It is off while EDGE_STOP_MARGIN_M = None. If
  you turn it on, Phase 0 pilots that come within that margin of the
  boundary are stopped and count as failed runs.
- Keep someone on the e-stop anyway: the safety stop depends on mocap.
