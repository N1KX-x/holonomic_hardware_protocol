HOW TO COLLECT TRAINING DATA FOR A LEARNED MODEL ON THE TEST PC
================================================================

These runs drive the Go2 with random velocity commands so a learned model
(for example a neural network) can be trained on how the robot really moves.
They are separate from Phase 0 and Phase 1 and never change their files.

Run every command below from inside the project folder on the test PC:

    cd /path/to/holonomic_hardware_protocol

Every trial uses the same command. Each run is saved as the next number
(trial_001, trial_002, ...), so nothing has to be edited between trials.


----------------------------------------------------------------------
0. ONE-TIME SETUP
----------------------------------------------------------------------

0.1 Copy the updated project folder to the test PC (USB, scp, ...). It must
    include collect_training.py and the new training section in config.py.

0.2 Check config.py on the test PC. The mocap, ROS and calibration values
    are the same ones used for Phase 0:

    MOCAP_CLIENT_IP, MOCAP_SERVER_IP, RIGID_BODY_ID
    CMD_VEL_TOPIC, STOP_TOPIC, NOVA_ENV_FILE
    YAW_OFFSET_RAD, MARKER_TO_BODY_X_M, MARKER_TO_BODY_Y_M
    WORKSPACE_X_MIN_M / X_MAX_M / Y_MIN_M / Y_MAX_M
    ALLOW_HARDWARE_EXECUTION = True

    Training values (leave them unchanged once the first trial is saved):

    TRAINING_SEGMENTS          commands per trial (20 x DT_S = 40 s)
    TRAINING_MIXED_PER_BLOCK   12 = 12 mixed trials in every 15 (80 %)
    TRAINING_RANDOM_SEED       sets the order of trial types
    TRAINING_PLAN_MARGIN_M     how far inside the workspace the planned
                               path must stay (0.5 m)

    Recommended:
    EDGE_STOP_MARGIN_M = 0.3   stops the robot near the mat edge. While it
                               is None, every trial prints a warning.


----------------------------------------------------------------------
1. CHECKS THAT DO NOT MOVE THE ROBOT
----------------------------------------------------------------------

1.1 Run the unit tests:

    python3 -m unittest discover -s tests -v

1.2 Check that Nova provides everything the command sender imports
    (should print "ok"):

    source ~/nova/env.bash && python3 -c "import rclpy, geometry_msgs.msg, unitree_go.msg; print('ok')"

1.3 Start the Nova Go2 driver in its own terminal and leave it running.
    Then, in another terminal where you have run "source ~/nova/env.bash",
    confirm it is listening (each should show Subscription count >= 1):

    ros2 topic info /cmd_vel_out
    ros2 topic info /webrtc_req

1.4 Preview the next trial. This prints its name, its type and a sample
    plan from the middle of the workspace. Nothing moves, nothing is saved:

    python3 collect_training.py


----------------------------------------------------------------------
2. COLLECTING TRIALS
----------------------------------------------------------------------

Keep Nova running. Keep someone on the e-stop for every trial.

2.1 Stand the robot somewhere near the middle of the mat. Any heading works.

2.2 Run one trial:

    python3 collect_training.py --execute

    The script reads the robot's pose from mocap, draws 20 random commands
    whose planned path stays inside the workspace, prints them, runs them
    (about 40 s), and saves the data. At the end it prints:

    trial_007 saved. E with the current nominal model: 1.234 m
    Next: trial_008 (mixed). Bring the robot back near the middle ...

2.3 Walk the robot back near the middle if it ended close to an edge, then
    repeat 2.2. One trial takes about 2 minutes including the walk back.

2.4 Plan for about 50 trials in the first session (1.5-2 hours, with
    battery swaps as needed). Stopping and continuing later is fine: the
    same command picks up at the next number.

2.5 To see progress at any time:

    cat data/training/trials.csv

    Each row is one trial: its type (mixed, vx_only, vy_only, omega_only),
    status (ok or discarded), segments sent, E, and start pose.


----------------------------------------------------------------------
3. WHEN SOMETHING GOES WRONG
----------------------------------------------------------------------

"... is within 0.5 m of the workspace edge; move it toward the middle"
"Could not draw a plan that stays inside the workspace"
    The robot did not move and nothing was saved. Move the robot toward
    the middle and run the same command again.

"Mocap is not tracking the robot"
    Nothing was saved. Check the rigid body in Motive and run again.

Safety stop, velocity runner error, or Ctrl+C during a trial
    Ctrl+C stops the robot. The trial's files are kept, the folder is
    renamed trial_NNN_discarded, and the reason is written to
    data/training/notes.txt. The next run uses the next number on its own.
    Do not rename or delete trial folders.

"trial_NNN saved, but its check failed: ..."
    The run finished and its data is kept as ok (for example a short
    mocap dropout). The reason is in the note column of trials.csv.
    Keep collecting.


----------------------------------------------------------------------
4. WHAT IS SAVED
----------------------------------------------------------------------

data/training/
    plans/trial_001.csv        the commands planned for the trial
    raw/trial_001/
        commands.csv           commands actually sent, with send times
        mocap.csv              raw mocap (uncorrected theta_raw)
        publish_log.csv        every ROS publication and stop request
    raw/trial_002_discarded/   a failed trial, kept for reference
    trials.csv                 one row per trial
    notes.txt                  reasons for discarded trials

Mocap is saved uncorrected, so the yaw offset and marker offset can still
be changed later during processing.

To take the data off the test PC, copy the whole data/training folder
(USB, scp, ...). Collect from one PC only, so trial numbers stay unique.


----------------------------------------------------------------------
SAFETY NOTES
----------------------------------------------------------------------

- The planned path stays TRAINING_PLAN_MARGIN_M inside the workspace, but
  the real path drifts from it by about 1 m over a 40 s trial. Only
  EDGE_STOP_MARGIN_M stops the robot at the edge, and it depends on mocap.
- Keep someone on the e-stop for every trial.
